Jira Rollup Agent — Summarization Prompt Design (Draft, not yet implemented)

Generated from planning discussion — reflects decisions made so far on chaining, role-weighting, and date-range handling. Not yet reviewed/confirmed as final.

Shared shape across all levels

User message always carries: ticket identity (type, Jira ID, title, status/assignee where applicable), the reporting date range, then the raw comments and/or child summaries.
System message carries the task instruction, weighting rule (if any), and output constraints (length, tone, no verbatim comment dumping).

Leaf level (Bug, Task, Spike, Subtask, StoryBug) — no weighting

"Summarize this Jira ticket's activity for a status report. Write 1-3 concise sentences covering current status, key progress, and any blockers. Treat all comments equally regardless of author. Synthesize — don't quote comments verbatim."
Ticket: {Type} {JiraId} — "{Title}" (Status: {Status}, Assignee: {Assignee})
Reporting period: {RangeStart} to {RangeEnd}

Comments:
- [{Timestamp}] {Author} ({Role}): {Text}
...

Story — no weighting, but includes child summaries

Same system prompt as leaves, plus:

"You are also given summaries of this Story's Subtasks and StoryBugs — incorporate their key points."

User message adds a second block after the Story's own comments:

Related sub-ticket summaries:
- [Subtask "{Title}"] {SummaryText}
- [StoryBug "{Title}"] {SummaryText}

Epic — Engineering Summary, Dev/QA-weighted

"Produce an Engineering Summary of this Epic for developers/technical leads: technical progress, bugs, blockers. Prioritize what Dev and QA commenters said; other roles are context but shouldn't dominate. Incorporate the work item summaries provided. 3-5 sentences."
Epic {JiraId} — "{Title}"
Reporting period: ...

Comments on this Epic directly:
- [{Timestamp}] {Author} ({Role}): {Text}
...

Work item summaries:
- [{Type} "{Title}"] {SummaryText}
...

Initiative — Business Summary, ScrumMaster/Stakeholder/EM-weighted

"Produce a Business Summary of this Initiative for stakeholders/leadership: overall status, risk, business impact. Prioritize what ScrumMaster, Stakeholder, and Engineering Manager commenters said; Dev/QA commentary is context but shouldn't dominate. Incorporate the Epic summaries provided. Avoid deep technical jargon. 3-5 sentences."
Initiative {JiraId} — "{Title}" (Priority Rank: {PriorityRank}, Status: {Status})
Reporting period: ...

Comments on this Initiative directly:
...

Epic engineering summaries:
- [Epic "{Title}"] {SummaryText}
...

Placeholder case (zero in-range comments)

For "No activity in this period" tickets, skip the LLM call entirely — hardcode the placeholder text deterministically rather than spending a call asking the model to say nothing happened.

Open questions to confirm

  • Is the weighting instruction wording clear enough, or does it need to be stronger/more specific?
  • Does including ticket Title/Status/Assignee as structured header context (not just raw comments) make sense, or should the prompt rely on comments alone?
